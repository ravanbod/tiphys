# Tiphys frontend (`web/`)

Vite + React 18 + TypeScript (strict) + react-router (BrowserRouter). The Go server embeds `web/dist` and serves it from `/` with a client-side routing fallback; every asset URL is root-relative, fonts are self-hosted (`@fontsource/ibm-plex-*`), and there are no inline scripts or inline event handlers.

## Run it

```
cd web
npm install
npm run dev            # Vite on :5173, proxies /api (ws:true), /auth, /healthz to http://localhost:8080
npm run dev:mock       # same, but with the in-browser mock API (VITE_MOCK=1), no backend needed
npm run typecheck && npm run lint && npm test && npm run build   # build output: web/dist
```

### Mock mode (`VITE_MOCK=1`)

`src/mock/` patches `fetch`, `WebSocket` and `EventSource` for `/api/v1/*` and `/auth/*`. It is loaded with a dynamic import behind the env flag, so it is not in the production bundle (verified: `grep -r mock-csrf-token dist` finds nothing). It covers every endpoint in `docs/api.md`.

- Persona: `?as=user|admin|auditor` (remembered in `localStorage` as `tiphys.mockRole`). Default `user` = Sara Moradi; `admin` = Reza Ahmadi; `auditor` = Leila Safavi.
- `?stale=1` simulates a stale Argo cache (project-scoped grants stop matching, banner appears); `?stale=0` clears it. `?recordingDown=1` makes exec refuse (`recording_failed`); `?recordingDown=0` clears it.
- Data: prod-1 / prod-2 / staging-1 / staging-2 clusters. prod-2 is unreachable (502 `cluster_error`), staging-2 is over-privileged. `payments-api` on prod-1 has an OOMKilled pod, a running CronJob (`expire-pending-charges`, `Forbid` -> `already_running`), a suspended one (`archive-reports`). On staging-1 `payments-api` exec / run-job are closed by a time window until Saturday 09:00 (Sara can use break-glass); `payments-worker` restart on prod-1 is closed by a holiday. `notifications-api` is Sara's logs-only case (`no_grant`) and its restart rollout fails with `ProgressDeadlineExceeded`. The Payments team's project grant includes `sync` and `rollback` (prod-1 `payments-worker` syncs automatically, so it cannot be rolled back; a rollback of `payments-api-config` would also apply a `ClusterRole`; only the middle deploy of a history can be rolled back to), so the Argo CD card offers Sync on the payments apps (except `payments-api-config`, which manages a `ClusterInput` and a `ClusterRole`: admins only until the Settings page allows `ClusterInput.fluentbit.fluent.io`, and then still for the `ClusterRole`); a sync of a `Degraded` app fails, and `OutOfSync` apps have pending changes (including a hidden Secret). Every namespace has a traffic graph: the first workload behind an Ingress with eight paths, the others behind HTTPRoutes on a shared Gateway; Sara's pending request #8 (restart on prod-1 `notifications-api`, 7 days) adds to her grant #9 when approved. In-cluster Services are the first workload's `-grpc`, a StatefulSet's `-headless` and a `legacy-admin` that selects nothing; on prod-1 `payments-worker` an Istio waypoint carries `-grpc` through a mesh HTTPRoute and `payments-ledger-headless` directly. Exec into the first `payments-api` pod on prod-1 gets a `warning` after about 20 s and `end` (`max_duration`) after about 5 min 20 s so the 5-minute warning can be seen.
- The fake exec shell understands `ls pwd whoami id hostname date echo env clear help exit`. Recordings and the command list are generated.
- Namespace page: three tabs chosen by `?tab=` (`workloads`, `events`, `traffic`). Events and Traffic are fetched only when their tab is first opened (per namespace) and kept when switching; Refresh reloads; a 403 explains inside the tab that it needs access to the whole namespace.
  - Workloads: the "Argo CD" card (shown whenever the namespace has Argo applications, regardless of `ARGO_UI`) and the workload list. CronJob rows get Run now for users with a `run-job` grant; "Job history" opens the namespace's CronJobs page.
  - Argo CD card: health, sync and last sync per application, a Sync button on every app, disabled with the reason on hover when the viewer may not sync it (dialog with the pending changes, typed confirmation in prod), and the name opens the details panel (Status, History, and Changes for users who hold `sync`). History names the portal user behind deploys started here and, for users who hold `rollback`, offers Roll back on earlier deploys (disabled with the reason for auto-sync, multi-source and changed-source deploys); its dialog loads the rollback plan (what the revision adds, what stays, a denial with the namespace or admin-only resources), asks for the name in prod and follows the operation like a sync; the icon next to the name links to `me.settings.argoUrl`.
  - Traffic (`components/TrafficFlow.tsx`, layout in `lib/traffic.ts`): four columns with SVG connectors measured from the boxes. Hover highlights a box's path; clicking pins it (several can be pinned; Escape, the background or Clear unpins); "+N more" and "Expand all routes" show every rule. What no external entry leads to (Services nothing exposes, Istio waypoints and their routes) is shown under an "Inside the cluster only" divider in each column; "Hide in-cluster Services (N)" hides it (memory only), and while hidden its problems are counted on the button.
- A CronJob's page opens on its own job history and has Run now in its header.
- Debug (`me.settings.debugEnabled`): pods get a Debug button next to Exec, both shown under the `exec` decision. It opens the exec page with `?mode=debug` (the connect dialog can switch between the container and a debug container), which connects to the `/debug` WebSocket instead of `/exec`. Sessions, Replay and Watch mark debug sessions. The mock enables it and uses the same fake shell.
- The mock checks `X-CSRF-Token` on every non-GET and the `csrf` query on every WebSocket, like the real server.
- Live changes: every 5–9 s something happens in a followed namespace (a container OOMKilled, a rollout with a new pod, a BackOff warning, a CronJob starting a job) and the mock data changes to match, so the refetched pages and the toasts show it.

## Layout

```
src/api/        types.ts (copied from docs/api.md), client.ts (CSRF, 401 -> /auth/login?next=, or /login?next= with local accounts), errors.ts (ApiError, toApiError),
                endpoints.ts (typed api.*), ws.ts (framing: binary = bytes, text = JSON control), sse.ts (operation stream), live.ts (GET /live)
src/lib/        pure helpers with Vitest tests: decision reasons, countdowns, log parsing, asciicast parsing, cron text, window preview, ...
src/context/    auth (Me), theme (system/light/dark + localStorage), break-glass dialog/provider, toast, shell context pill, live (changes stream + toasts)
src/components/ Icon (replaces the SVG sprite), Dialog (focus trap, ARIA), ActionButton (DecisionInfo -> .btn.dis + reason), Shell, XTerm, ...
src/pages/      user pages at the top level, admin/ and audit/ for the rest
src/mock/       in-browser API (dev only)
```

Role handling: every role gets Workloads (`user` and `auditor` per their grants). `user` and `auditor` get My access (grants, requests) and break-glass (`usesGrants` in the auth context); a `user` or `auditor` who manages a team (`me.managedTeams`) also gets My teams (`pages/MyTeams.tsx`: add and remove members, with the team's grants shown read-only, the team's access requests, and "Request access for this team", which opens the My access form with `?team=<id>`; the form's For picker then asks for the team and holds the team's grants as held; admins pick managers in the Managers card on Teams and see "for team X" on Access requests, where the merge preview reads the team's grants); admins also get Requests, Grants, Time windows, Users & teams, Clusters, Settings, Sessions, Audit. `auditor` additionally gets Audit, Sessions (+ replay, live watch) and read-only configuration pages (write controls are hidden). Wrong-role URLs redirect to the role's home (`/` or `/audit`). Break-glass lives in the user menu and in the denial hints/tooltips (only when the reason is `outside_window` or `holiday` and the viewer is a `user` or `auditor`); the active pill with countdown and "End now" is in the top bar on every page. The dialog's Starts picker schedules it for later (`datetime-local` in browser time, `parseStart`, at most 7 days ahead); the top bar then shows "Break-glass scheduled" with its start and Cancel, refetches `/me` when the start passes until it reads active, and pages that list what break-glass opens refetch on `breakGlassKey(me)` (it changes then too). In mode `approval` (`me.settings.breakGlassMode`, `lib/breakGlass.ts`) the same entry points read "Request break-glass" and send a request; while it is pending (`me.breakGlassRequest`) the top bar shows a "Break-glass requested" pill, the dialog shows it with Cancel, and `/me` is refetched every 10 s so an approval appears without a reload. Admins decide requests in the Break-glass card at the top of Access requests (`pages/admin/BreakGlassRequests.tsx`), with a duration up to the maximum and a note (required to reject). The access request list has a search (people, teams, scope names, reasons) and Cluster, Environment, Action and For (people or teams) pickers, applied in the browser (`lib/requestFilters.ts`) and remembered per admin in localStorage (`tiphys.requestFilters.<userId>`), so they are still set on the next visit; "Showing n of m" and Clear filters appear while any is set, and the page always opens on Pending. A batch (`batchId`, `lib/requestBatches.ts`) is one entry there, on My access and on My teams (`components/RequestGroup.tsx`); its decision card lists the namespaces with what approving each does (merge or new grant), unticked ones are rejected in the same call (`POST /access-requests/batch/{id}/decide`, a note is then required), and the button names the counts. The request form's namespace scope takes several namespaces (chips plus the searchable picker, at most 20): more than one is sent as a batch, and namespaces that already have every wanted action are left out. The grant editor does the same for a new namespace grant (More namespaces, at most 50, `formNamespaces` in `lib/grantForm.ts`): more than one goes to `POST /admin/grants/batch`, and the editor names the namespaces where the holder already has a grant (a new one is created beside it).

Settings page (`pages/admin/Settings.tsx`): the numbers, break-glass mode and Rocket.Chat are edited together and saved with Save changes; Protected namespaces and Argo CD sync (`pages/admin/SettingsLists.tsx`, chips with add/remove) apply at once. Removing protection and allowing a sync kind ask first, since both widen access. The kinds are saved from freshly read settings, and Save changes leaves them out of its body (the server keeps them), so neither overwrites the other.

Denial hints offer "Request access" (`lib/requestLink.ts`): the link names what was denied (`/access?request=1&cluster=&namespace=&action=`, plus `kind`/`name` for a workload action; for an app's sync, the namespace that denied it), and My access opens the request form filled with it. The form is shown only while the URL has `request=1` (the "Request access" button sets it; Cancel and Send remove it), so the grants and requests tables otherwise get the full width (their action chips wrap to at most two lines). A linked cluster the catalog leaves out is protected, where requests are refused, so the form says so and falls back to a listed one; a linked namespace an unreachable cluster cannot list stays chosen.

List filters live in the page's URL (`hooks/useUrlState.ts`, written with `replace`), so the browser's back button brings them back: Workloads, the namespace page (name, kind, events "Warnings only", traffic "Hide in-cluster Services"; its tab links keep them), Users, Grants, Sessions, and Audit (`lib/auditFilters.ts`). The hook holds the values in state that updates at once and follows URL changes it did not write, because the router applies URL changes in a transition, which must not drive a text input. Workloads also remembers its last filters for the tab and user in `sessionStorage` (keyed by user ID, since logging out and in as someone else keeps the tab) (`lib/workloadFilters.ts`), so the breadcrumb and sidebar links bring them back too; a link to a starred app (`?expand=`) neither restores nor clears them.

The portal draws every picker itself, so the open list has the page's font and theme (a native `<select>` or `<datalist>` opens in the OS's font): short fixed lists use `components/Select.tsx` (a button with a listbox, keyboard like a native select: arrows, Home/End, Page keys, type-ahead, Enter/Space, Escape; as wide as its longest option; `lib/selectNav.ts`), long ones `ComboBox`, and both open their list through `components/Popup.tsx`, at a fixed position at the end of `.app` (which holds the colour tokens), so scrolling tables and dialogs do not cut it off. `ComboBox` with `free` is a text field with suggestions (new environment names, timezones, the Audit filters). Do not add a native `<select>` or `<datalist>`. Long pickers are searchable (`components/ComboBox.tsx`, matching in `lib/comboFilter.ts`): focus shows the options, typing narrows them (every word, anywhere; label prefixes first; at most 200 rendered), arrows and Enter pick, Escape or leaving keeps the value (Escape does not close a surrounding dialog). Used for the namespace in the My access request form, the holder and namespace in the grant editor, the user, namespace and workload in the access checker, and the Holder filter on Grants. Workload checklists (request form, grant editor) get a filter box when they list more than 8. Grants also has a text search (`q` in the URL: holder, scope names, cluster, environment, note, author) applied in the browser on top of the API filters.

Live changes (`context/live.tsx`): `LiveProvider` keeps one `GET /live` stream per tab for the namespaces the mounted components follow with `useLive(target, refresh)`; it is reopened (after 300 ms) when that set changes. `refresh` gets the changes gathered until 400 ms pass without one (at most 2 s, at most every 1.5 s), or an empty list after a reconnect; pages refetch what the changes touch over REST, and poll slowly (60 s) while the stream is up. The home page's expanded namespaces, the namespace page, a workload's page, its logs page and the CronJobs panels follow. The "Live" pill in the top bar shows the stream's state and mutes toasts on the current page (in memory, per path; a reload unmutes). Toasts (`lib/liveToasts.ts`) cover only what the page follows: restarts, rollouts, job runs and a few warnings; repeats of one kind on a workload fold into one toast with a count, at most three are shown with "+N more". Animations (`styles/live.css`, off with `prefers-reduced-motion`): `useAnimatedList` marks table rows that appeared, changed or left between two versions of the data (not on the first load or a new page/filter), and `Bump` pops a value when it changes.

Disabled actions use `DecisionInfo`: `lib/decision.ts` turns `reason` / `reopensAt` / `closesAt` into text ("Exec in prod is closed until Sat 09:00", "Closes in 42 min") and picks the call to action (request access vs. break-glass).

## CSP and the replay player

The portal CSP (`default-src 'self'; style-src 'self' 'unsafe-inline'; ...`) has no `'wasm-unsafe-eval'`. asciinema-player compiles a WebAssembly module, which that CSP blocks. The replay page therefore feature-detects WebAssembly (`lib/wasm.ts`) and uses asciinema-player only when it can run; otherwise it uses a small xterm.js based player (`components/XtermCastPlayer.tsx`: play/pause, seek, speed, idle compression). Both support the command list click-to-seek and output search. If you add `script-src 'self' 'wasm-unsafe-eval'` (it allows WebAssembly only, not `eval`), the full asciinema-player is used automatically. Verified with a headless Chromium against the exact CSP above: no violations on any page.

## API gaps

Things the screens need that `docs/api.md` does not provide. The mock follows the proposals marked (mock); nothing here was assumed silently on the server side.

1. **Rejected WebSocket upgrades are opaque to browsers.** `docs/api.md` says denial / `recording_unavailable` are returned as HTTP errors before the upgrade, but a browser cannot read the status or body of a failed handshake. Proposal (mock): complete the upgrade and send `{"type":"end","reason":"denied"|"recording_failed","message":...}` before closing (the UI shows it in the connect dialog). Fallback implemented: after a handshake failure the UI re-reads the workload's `DecisionInfo` to explain the denial. A `503 recording_unavailable` can only be shown via the `end` message.
2. **My access "Available now".** `MyAccess.grants[]` has no availability. The UI derives it from `GET /clusters/{c}/namespaces/{ns}/workloads` (per distinct namespace) and, for Argo-project grants, from `GET /apps` access; unreachable clusters show "-". Proposal: add `availability: Record<Action, DecisionInfo>` (or just `allowedNow` / `reopensAt` / `reason`) per grant.
3. **`POST /access-requests/{id}/approve` narrowing.** The decision UI lets the admin narrow *actions* as well as duration. docs/api.md only has `note` and `durationHours`. Proposal (mock): optional `actions?: Action[]` (subset of the requested ones).
4. **Grant expired date.** `DecisionInfo` has no expiry timestamp for `grant_expired`, so the message is "Your access has expired." (My access has the dates).
5. **Display time zone.** The server gives no display zone. Dates use the browser zone; time windows use each rule's zone and grant expiry is entered in Asia/Tehran (the spec default).
6. **Audit filters.** "Break-glass only" is the server's `breakGlass=true`, so pages and the CSV export hold only break-glass events. No event total for the subtitle ("N events loaded"). No list endpoint for event types, clusters or environments for filter dropdowns (suggestions from `/admin/users` and `/admin/clusters`; environments come from the registered clusters, not a fixed list). Events carry no user role/team and no matched grant.
7. **Watch**: `ready` should carry `cols`/`rows` of the watched terminal (the UI already uses them when present).
8. **Teams change history**: `GET /audit?eventType=admin.change&entity=team&entityId=<id>&limit=10`, the team's own changes (grants on the team are not included).
9. **Clusters**: no Argo app count per cluster, no discovery list of Argo clusters (name is typed), no list of environment names (suggestions come from clusters and overrides), unspecified whether `PUT /admin/clusters/{name}` accepts an empty environment.
10. **Settings**: no storage-usage endpoint (the retention usage bars from the design are omitted); the 422 `details.fields` keys for settings are not specified (UI accepts `key` and `rocket.key`).
11. **Last-admin 409** has no fixed `code` (UI matches `last_admin` / message text). Please fix the code in docs/api.md.
12. **Grants / time windows / holidays**: 422 field key names not specified (UI assumes the camelCase JSON names); a team-scoped window's `scopeValue` is assumed to be the team name and a cluster-scoped one the cluster name; midnight-crossing windows are assumed to belong to the day they start on; no bulk holiday endpoint (CSV import does one POST per row and can hit the 30/min limit). `DecisionExplain` has no name for the blocking time-window rule (the checker infers it client-side).
13. **Auditor access to catalogs**: auditors read `/catalog/*` like users (for the request form); `POST /admin/access-check` and the grant editor stay admin-only, so auditors get read-only pages without the editor/checker.
14. **CSP**: see above (`'wasm-unsafe-eval'`).
15. `GET /audit/export.csv` and the log download are plain links (cookie auth); they cannot be exercised in mock mode (the log download is fetched as a blob there).

## Server decisions on the API gaps

Resolved in the Go server (see docs/api.md): 1 (refusals are delivered as an `end` message after the upgrade, with `code` and `decision`), 3 (`actions` narrowing on approve), 7 (`cols`/`rows` on watch `ready`), 11 (`409 last_admin`), 14 (`'wasm-unsafe-eval'` is in the CSP, so the real asciinema-player runs). Not changed: 2, 4–6, 8–10, 12, 13, 15 (the UI's fallbacks stay).
